# dashboards

Creates a "Kubernetes overview (<cluster_name>)" dashboard in its own folder,
built from the same signals as the alert catalog. A namespace selector at the
top scopes the workload panels.

| Row | Panels |
| --- | --- |
| Overview | Nodes not ready, pods not running, container restarts, missing replicas, failing synthetic checks, metrics targets down, and the cluster's firing and pending alerts |
| Resources | CPU and memory by namespace, top containers by memory (% of limit) and by CPU throttling, node CPU and memory |
| Workloads | Restarts per pod, deployments missing replicas |
| Synthetic checks | Status per target, response time, TLS certificate days left |
| Logs | Error-looking log lines, when `loki_datasource_uid` is set |
| Services | Requests per second, 5xx error rate and p90 latency per service, and the slowest routes, when `apm.enabled` is set (the root module passes `alerts.apm`) |

## Usage

```hcl
module "dashboards" {
  source = "github.com/Mosher-Labs/terraform-kubernetes-observability//modules/dashboards?ref=<commit-sha>"  # vX.Y.Z

  cluster_name              = "lab"
  loki_datasource_uid       = "loki"
  prometheus_datasource_uid = "prometheus"
}
```

The dashboard is regenerated on every apply, so edits made in the Grafana UI
are overwritten. Save a copy under another name to customize it.

## Inputs

| Name | Description | Type | Default | Required |
| ---- | ----------- | ---- | ------- | :------: |
| cluster\_name | Name of the cluster. Used in the dashboard title, its UID, and the alert list filter on the `cluster` label. | `string` | n/a | yes |
| prometheus\_datasource\_uid | UID of the Prometheus-compatible Grafana datasource the panels query. | `string` | n/a | yes |
| apm | Service-level metrics for the Services row: the same settings as modules/alerts' apm.
